# 建筑标准组件制作与扩展规则

## 1. 适用范围

本规则服务于 `scenes/building_workbench.tscn` 的平面驱动建筑原型。组件是生成器可复用的模型载体；建筑平面、楼层和材质参数始终保留为生成数据，正式 Mesh 不反向替代输入。

当前原型不替代 `docs/roadmap.md` 中 v0.17～v0.23 的槽位、正式 BuildingRecipe 和生产发布闭环。

## 2. 生成依赖

```text
PCGBuildingPlan
  → PCGBuildingFootprint（稳定 ID、平面、楼层、层高、种子、组件绑定）
  → 主体挤出 Mesh
  → 边 / 面 / 顶点 / 楼层锚点
  → PCGBuildingComponentDefinition
  → 标准组件 Mesh 实例
```

- 同一份轮廓同时驱动墙体、屋顶、立面和收边，禁止分别保存互不关联的位置。
- 每栋建筑通过 `building + purpose` 使用独立确定性随机流，禁止调用全局随机状态。
- 单栋编辑只重建该栋；其他建筑的节点、组件和随机结果保持不变。
- 非法轮廓、缺失组件或角色不匹配时保留上一份有效显示，并返回可读错误。

## 3. 目录与注册

1. 在 `assets/building_components/` 新建 `.tres`。
2. 资源脚本使用 `scripts/building/building_component_definition.gd`。
3. 填写稳定 `id`、显示名、角色、几何类型、尺寸和共享材质 ID。
4. 需要人工模型时设置 `custom_mesh`；否则使用内置 `geometry` 生成标准 Mesh。
5. 运行建筑回归或打开工作台，目录会按文件名排序加载；错误、重复 ID 和空 Mesh 会列入诊断。

新增组件不需要修改生成器。替换某栋建筑的组件时修改对应 `*_component_id` 绑定，不修改其他建筑。

## 4. 坐标、原点和尺寸

统一使用米制，Godot 的 Y 轴向上。

| 角色 | 局部坐标与原点 | 安装规则 |
|---|---|---|
| `WINDOW` | XY 为立面，+Z 朝外；原点为墙面上的组件中心 | 按立面开间和楼层居中 |
| `DOOR` | 同窗户；原点为墙面上的组件中心 | 最长立面的地面层入口 |
| `AWNING` | +Z 朝外；原点为墙面安装中心 | 由对应窗户位置和宽度派生 |
| `PARAPET` | X 沿屋顶边，Y 向上，+Z 朝外；原点为组件中心 | 按实际边长缩放 X |
| `CORNER_POST` | Y 向上；原点为立柱中心 | 位于轮廓顶点，按建筑高度缩放 Y |
| `ROOF_HATCH` | XZ 为屋顶平面，Y 向上；原点为组件中心 | 位于有效屋顶内部锚点 |
| `ROOF_DRYING_RACK` | XZ 为屋顶平面，Y 向上；原点为组件中心 | 屋顶锚点必须仍在轮廓内 |
| `WINDOW_DRYING_ROD` | XY 为立面，+Z 朝外；原点为墙面安装中心 | 由上层窗户派生；空杆和衣物版本共用角色 |
| `BALCONY` | XY 为立面，+Z 朝外；原点为栏杆/地板组合中心 | 由上层窗户和楼层高度派生 |
| `DOUBLE_DOOR` | 同立面组件；门框、门板和遮阳顶共用原点 | 由 `use_double_entrance` 替换普通入口 |

`size` 是默认局部 Mesh 的实际包围尺寸。框架、玻璃、面板和出挑部分共用同一原点，不得把原点移到模型前端。

## 5. 角色与几何

- `role` 决定允许的安装语义；`geometry` 只决定模型构造，两者不得混用。
- 新角色必须以追加枚举和对应放置规则实现，不能复用旧角色表达不同语义。
- 自定义 Mesh 必须封闭、绕序一致、无零面积三角形和非流形边，并提供法线与 UV0。
- 标准窗和门的第一 Surface 为框架，第二 Surface 为玻璃或门板；扩展材质槽时必须保持顺序兼容。
- 屋顶非矩形盖板由主体生成器直接三角化；不能用缩放盒体冒充任意轮廓屋顶。

## 6. 材质与性能

- 使用稳定 `material_id` / `accent_material_id` 引用 `MaterialLibrary` 共享材质，不为每个实例复制材质。
- 组件 Mesh 由定义缓存并复用；位置、旋转和缩放属于实例，不写回共享 Mesh。
- 立面组件按实际边长和层高限制数量；不要为了不可见细节增加无意义细分。
- 大面积布尔开洞不属于本原型；门窗使用框架和内嵌面板表达，后续开洞必须接入统一占用与验收规则。
- 门、窗和装饰组件必须参与同一占用检查；任何立面组件不得与无关组件重叠或伸入其他建筑实体。
- 凹角两侧需要按组件宽度与外伸深度保留净空；不能只在立面上计算中心点而忽略整个构件。
- 装饰必须记录宿主窗户槽位，只有宿主通过检查后才可以生成；宿主接触与其他组件碰撞必须分开处理。
- 一键修复通过重新执行当前建筑的入口、门窗和装饰放置求解完成，不得直接移动或删除其他建筑的组件。
- 屋顶组件先按女儿墙厚度和安全间距计算内缩可用区，再检查完整水平占地；晾衣架可尝试 0°/90°，必须避开检修屋，放不下时不得生成。
- 凹形屋顶使用多边形相交面积验证完整容纳，不能只判断中心点或四个顶点是否在轮廓内。
- 遮阳棚与大门遮阳顶的支撑杆必须从墙面低点连接至棚体外缘；不得以悬空短杆代替支撑。
- 窗下装饰默认使用浅花盆台（含矮栏杆与植物），深阳台需要独立入口门；带衣物的晾衣杆放在窗台附近，空杆可保持窗中位置。

## 7. 新增组件验收

- 目录加载无错误，ID 唯一，角色与绑定匹配。
- 默认、最小和最大合法尺寸下均有有效 Mesh。
- 修改平面顶点、楼层、层高和种子后，组件位置与主体保持正确关系。
- 修改建筑 A 不改变建筑 B 的 Mesh 实例或随机细节。
- 撤销、重做和保存所需输入均为 Resource 数据，不依赖生成的 NodePath。
- 自定义模型按 `docs/component_authoring.md` 的水密、UV 和材质要求另行验收。

## 8. 廊桥（Skybridge）组件与连接规则

廊桥是 plan 级生成结构：它不绑定单栋立面，而由 `PCGBuildingPlan` 上的结合点与廊桥定义驱动，生成器复用标准组件体系。

- **角色与几何**：追加 `Role.SKYBRIDGE` 与 `Geometry.SKYBRIDGE`。横截面单元在局部 XY 平面内定义（X 桥宽、Y 以桥面为 0 向上），Z 为 1 米切片厚度；`skybridge_part_groups()` 输出薄桥面、双侧扶手横档、出挑顶棚与等距立柱参数（frame/accent/roof/post 四组），第一表面为结构、第二表面为扶手、第三表面为顶棚，保持材质槽顺序兼容。侧面不封闭，立柱间距由组件 post.spacing 决定。
- **结合点**：`PCGSkybridgeConnector` 记录建筑 ID、立面边序号、边内位置和楼层；楼层决定桥面高度，起止楼层不同即生成坡道。结合点同时给 `building_generator` 提供立面避让区。
- **路径与编辑**：`PCGSkybridgeDefinition.nodes` 为持久路径节点，每节点 `tension` 控制转弯强度（1 自然穿过、0 圆角驻停、>1 加强）；`auto_lift` 记录交叉自动错开的抬升量，均可经节点工具继续编辑。
- **门洞交接**：结合点所在立面自动裁切内凹门洞（宽 = 结合点宽 + 0.3m，深 0.45m，墙面按全局高度带与 s 切口分条，屋面/地面使用同切口点的增广轮廓三角化，主体保持封闭流形），洞口放门套组件，桥端伸入洞道顶住背板，桥面与建筑楼板齐平。
- **交叉求解**：平面投影相交且横截面高度重叠超过 60% 的两条廊桥合并为一个 cross 结构；否则自动垂直错开（ID 较大者在上方，净空 0.6m）。判定只依赖生成数据，重建结果确定。
- **替换组件契约**：后续用其他标准组件替换连廊效果时，新组件必须保持以下约定，生成器、交叉求解、等距立柱与材质派生才能直接复用：
  1. 角色 `SKYBRIDGE`，横截面定义在局部 XY 平面（X 桥宽、Y 以桥面/楼层地面为 0 向上），Z 为 1 米切片厚度；`size.y` 即桥面到顶棚顶的总高。
  2. `skybridge_part_groups()` 返回五组数据：`frame`（沿桥连续扫掠的结构件，如桥面）、`accent`（两侧扶手，只允许贴近桥宽的边缘细件，禁止贯通全宽的板件）、`roof`（顶棚）、`post`（支撑顶棚立柱的 `size/center_y/spacing`）、`baluster`（两侧栏杆立柱的 `size/center_y/spacing/x`）、`portal`（桥端立面门户框的 `frame_width/protrude`）。等距生成职责在生成器，组件只提供参数，桥变长时立柱自动加密。门户框随廊桥一起生成与消失，删除廊桥即恢复墙面。
  3. 相邻件必须互相嵌入（重叠 0.01m 以上），禁止共面，避免 z-fighting；所有件在 1m 切片内封闭。
  4. 材质槽顺序固定：0 结构、1 扶手、2 顶棚；实例颜色由生成器按建筑配色派生（基色 ±深/浅），组件只提供材质 ID。
  5. 组件预览 Mesh 由工厂从同一组数据生成（frame+roof 为第一表面、accent 为第二表面），进入目录水密与 UV/法线检查。
- **验收**：廊桥 Mesh 封闭、带 UV0/法线；窗口避让后结合点开间无窗且剩余区间重排；同输入语义摘要一致；合并/错开阈值行为有回归覆盖（`run_skybridge_test.gd`）。
