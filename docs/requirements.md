# PCG 工具需求与工程结构

## 工程结构
- 根目录 `project.godot`：Surface Component PCG，保留表面组件、吸附与实体融合功能。
- `PipeWeaver/project.godot`：PipeWeaver · 管道 PCG，独立管道工具，禁止与组件版共用主脚本。
- 两个工程的 `.godot/` 缓存均不进入 Git。

## Surface Component PCG 当前需求基线
- 组件必须从资产库拖放到平面墙或半球圆柱组合主体，预览交叠时高亮主体。
- 右侧主体由真实圆柱与同半径上半球 CSG 并集构成，包含独立实体和轮廓。
- 放置后可沿原主体表面拖动，并从圆柱侧面连续跨赤道到半球，组件默认 0° 遵循表面法线。
- 选中组件提供角度与等比缩放手柄，并提供法线倾角数值输入。
- 最终缩放 = 用户等比缩放 × 邻域自动缩放；不同主体不得互相影响。
- 主体与组件使用封闭 CSG 融合，支持水密线框检查。
- CSG 最终显示网格必须按面夹角重建 smooth groups：曲面连续平滑，开洞与端面保留硬边。
- 水密线框直接显示最终融合网格的三角边线，不依赖视口调试绘制。
- 组件通过稳定材质 ID 引用 Autoload 共享材质库，不得逐组件创建重复材质；CSG 无材质切面继承宿主材质。
- 框架与玻璃使用共享 Material Profile，BaseColor、Detail、Normal、ORM 均可留空并自动回退；用户可在 Profile 资产或运行时右侧面板浏览填入、清除贴图，变更不得重建组件。
- UV0 用于表面纹理，程序圆环按真实弧长、深度和平面尺寸生成 UV；主体与 CSG 切面按平面、圆柱或半球进行世界尺度投影。
- 最终实体与线框显示按 8m 空间 Chunk × 共享材质合批，每个 Chunk 独立剔除并保留完整法线和 UV0。
- 组件根部默认嵌入 0.12m；根面位于局部负 Z，外沿位于正 Z depth，禁止方向反转。
- 圆窗采用根部大、外沿小的梯形圆台，默认 `root_flare = 0.18`，过渡内圈连接实际大根面。
- 每个组件可开关主体包裹过渡，厚度默认按曲率自适应并支持显式调整，弧度独立可调。
- 过渡厚度同时驱动径向宽度与自适应高度；弧度范围 -1～1，0 为直线斜面，正值为凹圆弧，负值为反向圆弧。
- 过渡 CSG 与直接渲染必须共享同一 Mesh；直接渲染用于可靠显示凹形 loft，线框使用对应 UV2 网格。
- 过渡 Mesh 按锚点、倾角、缩放、密度、LOD 和参数签名缓存，未变化时不得重建。
- 过渡密度支持 25%、50%、100%、200%，LOD 0/1/2 使用 1、0.5、0.25 系数；最终分段由组件、主体和 LOD 比例共同决定。
- 拱形窗使用下部 2/3 矩形 + 上部 1/3 椭圆弧的逆时针封闭轮廓，窗框、玻璃、开洞和过渡共用轮廓，禁止法线反向。
- 邻域压缩允许继续变小，但当前选中的压缩组件不得因再次选中或移开而自动恢复；未选中组件按原规则恢复。
- 手动缩放以当前实际尺寸为起点，允许从消失状态恢复；其他组件按选中组件实际尺寸参与挤压。
- 拖动中延迟凹形 CSG，最终融合刷新每 0.1s 最多一次，交互结束立即提交最新结果。
- 可选后合并编辑模式：只更新轻量主体/组件预览，禁止 CSG 变换、注册与刷新；支持合并选中组件和全部合并。
- 密度选择必须按真实数值映射，默认 1.0 显示 100%，LOD 与密度缓存签名保持一致。
- 同材质多 Surface 合批必须使用 `surface_index + old_index` 去重，禁止跨 Surface 错用顶点。
- 组件制作必须遵循 `docs/component_authoring.md` 的坐标、根部、封闭 Mesh、UV、材质和验收规则。
- 过渡顶面法线必须由根部 XY 径向方向与正 Z 高度共同计算，禁止混入内外圈深度差或使用反向平均法线。
- 提供默认启用的 `surface_components` EditorPlugin，在编辑器内创建三类主体、从组件库拖放、选中编辑、后合并与删除，无需先运行示例场景。
- 编辑器创建的主体与组件必须可随用户场景保存；组件保存资产资源、相对主体 `NodePath`、锚点、角度、缩放和过渡参数，重载时重建预览、CSG 与注册关系。
- 插件必须声明处理 3D 节点并同时处理资产按钮与视口的松开事件，确保拖动结束后提交真实组件而非残留 ghost。
- 当前版本为 v0.16.2，版本写入根目录 `project.godot`。

## 平面驱动建筑复现原型
- 主场景提供“打开建筑平面工作台”入口；独立场景为 `scenes/building_workbench.tscn`，保留原表面组件示例。
- `PCGBuildingPlan` 保存多个带稳定 ID 的面岛；`PCGBuildingFootprint` 保存二维轮廓、楼层、层高、种子、材质和标准组件绑定。
- 同一轮廓驱动封闭主体、屋顶、立面开间、门窗、女儿墙、墙角柱、遮阳棚和屋顶检修屋，不以随机撒点代替几何派生。
- 十一份基础组件位于 `assets/building_components/`，由 `PCGBuildingComponentCatalog` 统一加载、校验和按角色绑定；新增规则见 `docs/building_component_authoring.md`。
- 装饰库包含屋顶晾衣架、有/无衣服的窗外晾衣杆、小阳台及带遮阳顶的双门入口；晾衣杆变体使用相同角色和独立确定性选择，双门通过 `use_double_entrance` 显式启用。
- 屋顶装饰锚点必须位于轮廓内；阳台和晾衣杆从上层窗户派生，楼层或平面变化后与主体同步重建。
- 屋顶晾衣架必须先扣除女儿墙厚度和安全间距，再用完整底座/横杆占地检查容纳；支持 0°/90° 放置并避开检修屋，无法容纳时不得生成。
- 门、窗和立面装饰必须统一检查占用、凹角/转角净空和其他建筑实体；入口优先预留并从满足净空的候选中选择，不得插入相邻建筑。
- 阳台、晾衣杆和遮阳顶必须关联实际存在的宿主窗户；只允许与宿主发生设计上的接触，窗户被规则拒绝时不得继续生成其装饰。
- 右侧提供“修复选中建筑”，只重新求解当前建筑并报告阻止的立面组件数量；细节种子修改后立即自动重建，无需应用按钮。
- 工作台支持面岛选择、顶点拖动、新增、中心轴切分、删除、楼层/层高/种子编辑和撤销/重做；数值框焦点不得吞掉全局撤销快捷键。
- 顶视图支持左键拖动空白区域、右键或中键平移；顶视图外右键拖动环绕三维相机，两条输入路径不得互相抢占。
- 顶视图支持 25%～800% 光标中心滚轮缩放、按钮缩放和一键适配；适配范围包含建筑轮廓、结合点与廊桥节点。
- 建筑内部拖动执行整栋平移，顶点拖动只改变轮廓；整栋平移保留稳定 ID、进入一次撤销记录，并同步依赖它的结合点和廊桥。
- 主体操作归入“建筑主体编辑”，连廊操作归入“廊桥编辑”；主体模式明确命名为“建筑主体平面编辑”。
- 顶视图内部提供 −、＋和四箭头向内的适配图标，不占用主体操作列表；独立窗口使用相同视图控件。
- Shift+单击切换建筑多选，保留主选中建筑供参数和修复使用；融合严格作用于显式选中集合，至少两栋且轮廓相交/相接时按钮才启用，否则保持灰色。
- 新建建筑使用按新建 ID 派生的确定性随机流，生成尺寸、矩形/L 形轮廓、楼层、细节种子、轻微旋转和墙面颜色。
- 新建位置在当前建筑群外围与空隙中进行 32 个候选采样，排除轮廓重叠，并按既有建筑面积、距离和中心距离选择低密度且仍接近建筑群的位置；撤销后同 ID 重建必须复现。
- 相交或相接且无未处理廊桥连接的建筑可执行轮廓融合，保留主选中 ID、进入撤销历史；中心切分后可继续独立编辑。
- 斜坡演示按轮廓采样地形，建筑保持水平并在低侧生成封闭基础；坡面平移自动更新基准标高、基础、立面和结合点，地形坡度纳入重建签名。
- 主体模式与结合点/桥节点模式必须隔离：桥节点编辑不得修改或重建主体，主体平移时其上结合点必须跟随。
- 提供强制原生窗口的独立细节视图，与原顶视图共享平面、选择、编辑模式、历史与重建结果；窗口内编辑必须驱动主场景联动。
- 每栋建筑使用独立确定性随机流，局部编辑只替换受影响建筑；非法输入保留上一份有效显示并报告错误。
- 建筑回归命令为 `godot --headless --path . -s scripts/tests/run_building_test.gd`，并纳入 `tools/run_gate.sh`。
- 本原型不宣称已经完成正式 BuildingRecipe、槽位生产闭环、任意布尔开洞或城市级布局；这些仍按路线图后续阶段执行。

## L0 资产任务当前基线
- `surface_components` 面板顶部提供“资产任务”入口，打开“L0 资产任务与精度规范”窗口。
- 支持新建、选择、校验、保存和重开任务；非草案状态必须满足分配级必填、尺寸、预算和接口校验才能保存。
- 任务覆盖类别、用途、风格、尺寸、原点、轴向、根部、接口、固定/可变/禁止特征、变体和状态。
- 精度任务包含 LOD0/1/2 三角预算、贴图尺寸、材质预算、UV 策略和碰撞策略。
- 支持人工、AI、外部和程序来源；AI 必须记录工具、提示词和种子，候选引用可追加且不得覆盖来源记录。
- 任务使用 Resource 模型，经自定义 JSON 编码和 `format_version` 信封原子保存到 `assets/tasks/`，提供门、窗、支架、招牌四个示例。

## L1 资产标准化当前基线
- 面板顶部提供“资产标准化”入口，打开候选 Mesh/PackedScene 的验收、校准、试装和发布窗口。
- 几何检查覆盖零面积面、开放/非流形边、法线、UV0、材质与尺寸/预算；严重错误不得伪装修复。
- 支持尺寸、轴向、根部和原点校准，并在平面、圆柱、半球圆柱主体上试装。
- 标准资产包含稳定 ID、任务与来源、规范化 Mesh、材质 Profile、验收报告、白盒、真实 LOD 和五类占用区域。
- 正式发布到 `assets/published/`，JSON 清单与每级 Mesh 文件必须可重载；重复 ID、缺 Mesh、缺报告或缺依赖必须拒绝。
- 碰撞层/掩码与占用语义遵循 `docs/component_authoring.md`；LOD 不可达或直通必须披露。

## 基础生产闭环与版本状态

### 当前已实现
- L0 支持手工建立任务、精度/接口/来源校验和原子保存。
- L1 支持候选几何验收、校准、试装、真实 LOD、占用和正式发布/重载。
- 当前尚未实现白盒占位批量提取、需求归并、统一生产收件箱、槽位绑定和 BuildingRecipe 纵向闭环。

### 必须贯彻的生产闭环
- 固定顺序为：已确认概念设计 → 建筑功能白盒/组件占位 → 批量提取并归并标准组件需求 → 批量生成 L0 任务 → 按概念稿风格分发给 Tripo/Meshy、人工或程序生成器 → 统一 L1 验收发布 → 按槽位批量绑定并替换占位显示 → BuildingRecipe 保存、重开和局部重建。
- 白盒组件占位是资产需求来源，追踪链固定为 `slot_id → L0 task → candidates → published asset + version → slot binding`。
- 需求按组件族和兼容规格批量归并；已有合格库资产和任务优先复用，只为缺失或不合格需求创建生产任务，禁止每个实例调用一次 AI。
- L0 任务必须携带概念稿/风格包引用、固定/可变/禁止特征、接口、尺寸范围、占用、LOD 和材质预算。
- 人工、AI 和程序候选进入同一收件箱与 L1 验收链，任何来源不得绕过标准化。
- “替换白盒”只更新显示与绑定；功能白盒、槽位、接口、碰撞和占用数据必须持久保留。
- 候选失败时，白盒、既有绑定、其他槽位和发布目录必须零副作用。

### 新增前置契约（v0.17～v0.20）
- v0.17：冻结 ComponentSlot、RequirementSpec、ProductionBatch、CandidateEnvelope 和资产版本依赖，建立统一收件箱与生产分发。
- v0.18：建立功能白盒占位、批量需求提取、兼容归并、库资产/旧任务复用和批量任务生成。
- v0.20：建立 SlotBinding、批量绑定与替换、BuildingRecipe 保存重开、局部重建和 `G3A_SlotLoop` 端到端验收。

### 未来在线 AI 接入
- v0.30 只承担通用外部命令 API、权限、审计、配额和规模化自动化，不再把 Tripo/Meshy 当作首次生产接入。
- 在线服务不可用不得阻塞本地人工/程序候选和离线收件箱闭环。

## 版本规划
- 使用语义化版本 `主版本.次版本.修订号`。
- 新功能且向后兼容时提升次版本；缺陷修复提升修订号；不兼容变更提升主版本。
- 长期建筑群编辑系统按 `docs/roadmap.md` 的集成里程碑执行；`0.x` 阶段的数据格式不兼容以格式版本、迁移器和旧样本回归管理，`v1.0.0` 后恢复常规主版本规则。
- v0.14 的稳定 ID、命令、随机流、宿主接口、重建签名和原子保存遵循 `docs/core_contracts.md`。
- 共享核心唯一物理来源为根工程 `addons/pcg_shared/`，PipeWeaver 与测试消费者经各自 `addons/pcg_shared` 链接使用；禁止双向复制同步，禁止合并两个主程序。
- 每次需求或缺陷修改同步更新本文件与 `docs/changelog.md`。
- 每次修改单独提交，提交信息采用 `type(scope): summary`，不得在提交中混入无关工程文件。

## PipeWeaver 当前需求基线
- 当前集成基线为 v0.16.2，版本写入 `PipeWeaver/project.godot`。
- 在同一立体表面通过起止点或 Paint 创建管道。
- 起止点允许位于两个不同主体，完整比较候选连接，以两侧表面路径与跨接距离之和最短为准。
- 双主体路径逐点记录所属碰撞体，平滑投射、拖动和角度设置使用对应主体。
- 连续管体、自动接头、法线正确，管体和接头均按世界尺度平铺 UV0；UV2 独立用于每管 AO。
- 管道使用共享 Material Profile，BaseColor、Detail、Normal、ORM 均可留空并回退到程序化默认贴图；右侧 PBR 面板支持浏览填入和清除，变更同步普通与 AO 材质变体。
- 未启用 AO 的管体共用同一材质，AO 开启后仅按管道增加独立纹理变体；自定义共享贴图不得覆盖每管独立 AO。
- `assets/presets/*.tres` 定义管道类型，切换预设立即替换当前或全部选中管道，多选批量替换不增加完成计数。
- 替换保持路径、控制点、主体、角度、离墙偏移和 UV2，仅更新直径、材质、贴图、分段与优化参数；每根材质快照独立。
- 自动网格优化按曲率减少长直段纵向分段，弯道、变径和离墙变化段保持精细采样。
- 支持贴图尺度联动、直线角度阈值和手动统一步长，减面不得造成 UV 拉伸。
- 直径分段及独立变径。
- 中间控制点拖动、追加、插入、删除和撤销。
- Paint 点击现有路径直接插入控制点。
- Paint 允许在同一主体的多个面之间一笔绘制；法线变化超过 45° 时自动识别棱边。
- 起止点、Paint、手动插入与拖动统一在路径重建时补出棱边控制点，禁止直穿附着物。
- 棱边默认生成硬转角与接头，初次生成即体现主体 90° 转折，可后续改为平滑弯头。
- 每节点平滑/硬直角、路径内夹角及 2～32 段独立圆角细分。
- 完成当前管道后冻结；新建下一根使用独立 Pipe_XXX 节点，旧管体不得被覆盖。
- 所有管道均保存完整 PCG 快照，可重新选中并恢复控制点和参数继续编辑。
- 选择模式支持单选、Shift/开关多选及全选；恢复编辑限单选。
- 多选管道分别按 8m 空间 Chunk × 共享材质合并为固定 Mesh，保留 UV0、UV2、材质、变换和逐 Chunk 层 2 拾取，PCG 数据用于之后恢复。
- 每节点独立离墙偏移，并提供蓝色 Z 轴手柄和数值输入。
- 最终离墙量 = 当前管道全局表面间隙 + 节点独立偏移。
- 操作面板左右留白 10px，默认字号 15、标题 20、提示 14。
- 完成/新建按钮位于右侧首屏。

## 工作方式约束
- 新需求不得为每次验证另开 Godot 窗口；只重用一个 PipeWeaver 实例。
- 版本对比通过 Git 提交，不通过多窗口并存。
- 双工程 headless 门禁统一运行 `tools/run_gate.sh`；也可用 `GODOT_BIN` 指定 Godot 可执行文件。
- 根工程独立 smoke 为 `godot --headless --path . -s scripts/tests/run_smoke_test.gd`，原 `-- --smoke-test` 入口保持兼容。
- PipeWeaver 独立 smoke 为 `godot --headless --path PipeWeaver res://tests/pipeweaver_smoke.tscn`，必须覆盖真实生成、路径、内存重编辑与多 Surface 合批。
- 图形输入、截图和性能按 `docs/performance_baseline.md` 在本机图形会话验证，不以 headless Dummy Renderer 代替。
- 每个功能版本必须由开发侧先完成发布验证，提供真实结果、证据、使用方式和用户验收清单；流程遵循 `docs/release_acceptance.md`。
- 发布报告保存到 `reports/release_verification/<version>/`，包含日志、关键场景截图、已知限制和反馈步骤；不得把未验证交互写成已通过。
- 每次需求变更同步更新 `docs/requirements.md` 与 `docs/changelog.md`。
