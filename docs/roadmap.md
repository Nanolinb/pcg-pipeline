# 大型风格化建筑群 PCG 编辑系统 Roadmap

## 1. 目标与使用方式

本文把长期目标拆成可执行、可验收的集成版本。最终系统基于 Godot，提供从资产生产、组件标准化、建筑样本装配到大型城市群生成与环境融合的多尺度编辑能力。

核心原则：

- 引擎风格无关，艺术家通过风格包、资产、样本和规则定义合法设计空间。
- AI 只生产候选资产、参数或方案；标准化、约束校验和最终提交由引擎负责。
- 所有层级保存可恢复的生成数据，正式 Mesh 是可缓存结果，不是唯一数据源。
- 白盒是持久代理，不是正式生成前的一次性草稿。
- 自动生成必须服从连接、碰撞、遮挡、净空、地形和人工锁定约束。
- 修改局部内容时，只重建受影响的依赖范围。

本文是执行计划，不代表这些功能已经实现。每个版本必须满足验收和全局质量门禁后，才能作为后续版本的稳定前置。

## 2. 当前基线与版本规则

### 2.1 已确认基线

- 根工程 Surface Component PCG：`v0.12.0`，Godot 4.6，GL Compatibility。
- 已有能力：表面组件、平面/圆柱/半球主体、CSG 融合、过渡、共享材质、世界尺度 UV、Chunk 合批、轻量预览、基础 EditorPlugin。
- PipeWeaver：独立工程，具备表面路径、跨主体路径、参数化管体、接头、支撑相关基础、PCG 快照、重编辑与固定 Mesh。
- 当前 PipeWeaver 工作区存在未提交修改。开始迁移前必须保留并复测这些内容，不得用清理或覆盖的方式取得“干净基线”。

### 2.2 版本编号

- 从 `v0.13.0` 开始按集成里程碑递增。
- 版本号属于整个计划，不允许资产线、建筑线和城市线分别占用同一个版本号。
- 每个 `0.x.0` 可以包含多个小提交；验收失败时以修订版修复，不提前开始依赖它的下游工作。
- 不兼容的文档格式或公开 API 变更必须带格式版本、迁移器和旧样本回归。
- `0.x` 阶段的数据格式不兼容通过格式版本管理，不因此提升主版本；`v1.0.0` 之后恢复 `docs/requirements.md` 的常规语义化版本规则。
- `v1.0.0` 代表第一条完整生产链达到发布标准，不代表所有远期功能均已完成。

### 2.3 完成定义（每个版本均适用）

一个版本只有同时满足以下条件才算完成：

- [ ] 执行项全部实现，未以手工整理最终 Mesh 代替生成数据。
- [ ] 既有 headless / 图形回归通过；尚无回归的工程以本版本新建回归为准。
- [ ] 新增验收已转成自动测试或可重复的人工步骤。
- [ ] 保存、关闭、重新打开后，参数、引用、随机种子和编辑状态可恢复。
- [ ] 同一输入与随机种子产生一致的语义结果和黄金样本。
- [ ] 非法输入有明确错误，不静默跳过、不生成已知破损结果。
- [ ] 未改变的对象保留原数据与显示实例；无无关全量重建。
- [ ] `docs/requirements.md`、`docs/changelog.md` 和相关制作规范同步更新。
- [ ] 版本号、变更记录和实际交付一致。

## 3. 总体依赖关系

```text
v0.13 基线与回归
  → v0.14 公共数据、命令、随机与宿主契约
  → v0.15 L0 资产任务单
  → v0.16 L1 修复、标准化与验收
  → v0.17 组件接口、占用与候选资产晋升
  → v0.18 参数化组合件
  → v0.19 路径网络与支撑系统
  → v0.20 建筑样本工作台
  → v0.21 立面、屋顶与收边子系统
  → v0.22 样本参数化、覆盖与局部重建
  → v0.23 白盒、LOD、建筑端口与首个风格包
  → v0.24 场地、地形、路网与地块
  → v0.25 建筑代理布局与样本绑定
  → v0.26 入口接路、落地与街区局部重生成
  → v0.27 多街区、风格分区与城市级变化
  → v0.28 复杂融合：贴邻、城墙、台阶和桥梁
  → v0.29 世界流送与规模性能
  → v0.30 自动化、AI 与外部生产 API
  → v1.0 生产链发布验收
```

依赖规则：

- `v0.15～v0.23` 中，资产 UI、组合件内容和性能 Spike 可并行，但不得绕过已冻结的数据契约。
- `v0.24` 可以在 `v0.22` 后开始场地算法预研；其正式前置是 `v0.23` 的白盒、LOD 与建筑 Port 契约，不以风格包内容制作完成为前提。
- AI 外部服务接入不是建筑生成链的硬前置；候选目录和人工导入先打通，在线 API 延后到 `v0.30`。
- GDExtension 不是默认答案。先测量，达到性能触发条件后再迁移重型算法。

| 风格包 | 语义资产映射、材质、比例、规则、随机权重、细节与稀缺性预算 | v0.23；样本和街区 |

### 4.2 固定测试场景

| 场景 | 内容 | 引入版本 |
|---|---|---|
| `G0_Component` | 平面、圆柱、半球主体与现有圆/方/拱窗 | v0.13 |
| `G1_Pipe` | 跨面、跨主体管道，冻结、重编辑、AO 与 Chunk 合批 | v0.13 |
| `G2_Assembly` | 门、入口、阳台、楼梯、主管和支撑的标准立面 | v0.19 |
| `G3_Building` | 首个建筑样本；v0.21 扩为三种原型及固定变体 | v0.20 |
| `G4_Block` | 带高差的小街区，含地块、建筑、入口道路和局部融合 | v0.26 |
| `G5_Districts` | 至少三个风格权重不同的街区，用于规模与隔离测试 | v0.27 |

黄金样本在引入版本固化，至少记录语义哈希、网格哈希与统计、材质引用、随机种子、截图和参考硬件性能。固化后哈希变化必须按行为变更审核，不能无记录更新基线。

- 语义哈希：生成数据经规范化序列化后计算 SHA-256；字段顺序固定，浮点量化精度统一为 `1e-5`。
- 网格哈希：顶点、索引和材质槽经相同规范化规则后计算 SHA-256。
- 自动确定性门禁以语义哈希为准，网格哈希用于几何回归；截图归档到 `reports/golden/` 并人工审核。
- 截图与真实输入 smoke 是参考硬件上的本机图形步骤，不进入无显示环境的 headless 门禁；headless 只承担数据与几何回归。
- 黄金基线绑定 Godot 确切版本和平台。升级引擎属于环境变更，必须先重录新旧基线再比较。

## 5. 分版本执行计划

### v0.13.0 — 基线、回归与迁移防护

**目标**：在继续抽象前，证明现有功能可重复验证，并保护 PipeWeaver 未提交工作。

**前置**：当前 `v0.12.0`。

**执行清单**：

- [ ] 记录并保留当前两个工程的工作区状态；复测现有 PipeWeaver 修改，不以覆盖或删除方式清理。

- [ ] 将根工程 smoke 从主场景生命周期中解耦，保留原命令入口和图形输入测试。
- [x] 为 PipeWeaver 建立最小 headless 回归，覆盖路径、管体、接头、内存快照重编辑和合批。
- [ ] 固化 `G0_Component`、`G1_Pipe` 的网格统计与日志基线；截图在本机图形会话补齐。
- [x] 建立统一门禁：headless 数据/几何回归与版本一致性自动运行，图形 smoke 和截图作为参考硬件步骤。
- [ ] 对共享代码做单源载体 Spike；两个主程序保持独立，验证独立 addon/包可被两个工程及最小第三方测试场景加载。
- [ ] 在一次性测试副本中验证清理 `.godot/` 后的重导入，检查共享包 `class_name`、`uid://`、Autoload 和插件缓存冲突。
- [ ] 记录当前重复脚本、功能分叉、根工程未引用管道文件和已知缺陷，冻结后续迁移顺序。
- [ ] 记录两个工程当前 RID 清理警告及退出时对象/RID 基线，作为资源稳定门禁的对比起点。

**验收**：

- 两个工程的 headless 回归可分别通过命令行运行，失败时返回非零退出码；图形输入路径在本机单独验证。
- 人为注入一个合批或路径回归时，对应测试必须失败；恢复后全绿。
- 复测证据存入 `reports/baseline/`，包含功能清单、操作步骤、截图或日志哈希；现有 PipeWeaver 修改未发生内容丢失。
- 共享载体 Spike 明确独立包归属与加载方式；迁移后共享包无重复 `class_name`，干净重导入无 UID/类缓存冲突。

**禁止进入下游的情况**：基线无法复现、现有修改被覆盖、共享载体仍需双向复制同步且没有单源迁移方案。

### v0.14.0 — 公共编辑与生成内核

**目标**：建立所有后续资产和样本编辑器共用的数据与编辑纪律。

**前置**：v0.13.0。

**执行清单**：

- [ ] 按 BASE-05 决策建立不属于任一主程序的独立共享 addon/包，依据基线清单逐个迁移重复脚本，两个主程序均以插件方式加载；此后禁止双向复制同步。
- [ ] 建立稳定 ID、资源格式版本、生成器版本和迁移器接口。
- [ ] 建立编辑命令模型，把创建、删除、变换和参数编辑纳入 UndoRedo；连续拖动合并为一条命令。
- [ ] 所有生成数据采用临时文件 + 原子替换，保留一份轮换备份；检测到写入中断时提供恢复，不直接覆盖最近一致状态。
- [ ] 实现按 `world / district / parcel / building / assembly / purpose` 派生的独立确定性随机流；派生方案带版本号，新增作用域只追加键，不改变既有派生序列。
- [ ] 建立最小依赖节点、dirty 标记和重建签名；不提前实现通用复杂 DAG 平台。
- [ ] 抽象表面宿主接口：射线锚点、表面坐标、法线/切线、路径数据和占用查询。
- [ ] 让现有平面、圆柱、半球主体通过适配器实现接口，保持行为不变。
- [ ] 统一缓存签名和缓存统计，覆盖现有过渡 Mesh 缓存。

**验收**：

- 两个工程和最小测试消费者从同一共享包加载核心，扫描无重复核心 `class_name`，主程序仍各自独立。
- 创建组件 → 改参数 → 撤销 → 重做后完整恢复；一次拖动只产生一条历史记录。
- 注入一次写入中断后，重开可恢复到最近一致生成数据，备份和恢复提示均可验证。
- 同一随机流重复 1000 次抽样结果一致；修改 A 分支不改变 B 分支序列，既有键的派生结果不因新增作用域改变。
- 新增一个测试宿主只需实现宿主适配器，不修改组件和路径核心。
- 同签名缓存命中、参数变化失效、无关对象显示实例保持不变。

### v0.17.0 — 组件接口、候选晋升与版本依赖

**目标**：统一组件之间的装配语言，并打通人工/AI 候选的非破坏晋升流程。

**前置**：v0.16.0。

**执行清单**：

- [ ] 冻结 Socket / Port 类型：附着、开洞、承力、路径、入口、设备和视觉占用。
- [ ] 为接口增加兼容标签、允许尺寸、方向、根部嵌入、必要净空和默认碰撞层分配。
- [ ] 建立候选收件箱，支持目录/压缩包和 manifest 导入；此版不依赖在线 AI 服务。
- [ ] 保存生产者、工具版本、提示词、种子、源文件和人工修复记录。
- [ ] 支持固定功能核心 + 可替换外观壳，防止外观变体破坏安装接口。
- [ ] 建立组件版本和依赖清单；加载样本时报告缺失或 incompatible 版本。
- [ ] 项目实例默认固定引用库组件版本；显式升级前列出受影响样本，并通过同一 UndoRedo 提交引用升级。
- [ ] 将全部已发布组件迁移到正式 Socket schema；v0.16 发布时先按本版草案字段写入，迁移不得破坏旧场景。

**验收**：

- 合格、拓扑损坏、尺寸超规三个候选得到不同验收结果，只有合格件可发布。

**验收**：

## 6. 非功能质量门禁

### 6.1 自动门禁

| 维度 | 最低验证要求 |
|---|---|
| 数据兼容 | 旧 Resource/Recipe round-trip；缺失依赖和版本错误可诊断 |
| 确定性 | 同输入、版本、种子的语义哈希一致；黄金网格哈希按审核变更 |
| 几何 | 实体无零面积面和非流形边；有向体积符合组件手册的朝外符号约定；关键样本水密 |
| 连接 | Socket 兼容、端点明确、入口可达、必要连接不静默丢失 |
| 碰撞与遮挡 | 允许嵌入和非法碰撞分离；入口、门窗、视觉重要区可校验；碰撞层/掩码符合约定 |
| 导航与运行时 | 入口到道路存在导航路径；无 EditorPlugin 的运行时实例化可重建并行走 |
| 局部性 | 无关对象语义哈希和显示实例不变；重建范围有界 |
| 撤销 | 所有提交操作可回退和重做，连续交互正确合并 |
| 性能 | 对照上一已发布版本同场景数据，交互目标 30 FPS，性能回退不超过 10% |
| 资源稳定 | 相对 v0.13 记录的对象/RID/警告基线，无新增持续增长或泄漏错误 |
| 外部 API | 非法候选零副作用，离线可用，来源和种子可审计 |

参考硬件必须在 `docs/performance_baseline.md` 记录 CPU、GPU、内存、操作系统、驱动、Godot 和渲染器；更换硬件后重新录制基线。性能报告必须注明预热次数、采样窗口及中位数/P95 口径。更换内核或渲染路径时，先记录新旧基线再比较，不把测量环境变化误判为性能回退。

### 6.2 人工门禁

- 参考风格截图对比：主体比例、包边、管网、支撑、色彩和人尺度是否保持一致。
- 积木式编辑：艺术家不编写脚本即可完成标准样本装配、保存和变体。
- 冲突处理：问题能定位到建筑、立面、组件或路径，不只有全局错误。
- 大场景编辑：白盒、正式、LOD 和流送切换可理解，不造成编辑对象丢失。

## 7. 暂缓与独立后续项目

以下内容不应挤入首条生产链的关键路径：

- 全室内生成和完整房间级布局。
- 交通仿真、复杂经济分区和城市生长模拟。
- 任意拱桥、复杂城门楼、特殊桥型和大型水系统仿真。
- 完全自由文本生成可发布级功能组件，跳过标准化验收。
- 未测量前全面改写 GDExtension 或 GPU 生成器。
- 多用户实时协作、自动合并冲突和完整版本管理平台。
- 为了统一而合并 Surface Component 与 PipeWeaver 主程序。

这些能力可以在对应核心稳定后单独立项，复用既有契约，不改变本路线图的依赖关系。
